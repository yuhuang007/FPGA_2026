# 网口前摄视频发送操作：3.6.1 SOURCE_MAP + m407

适用配置：电脑录像送入FPGA网口1，作为逻辑前摄；FPGA网口2将完整前摄上传到香橙派，由m407识别并在网页叠加。本页是操作说明，不代表已经完成上板验收。

## 1. 新方位与接线

| 方位 | 输入 | 四宫格位置 |
|---|---|---|
| 前摄 | 电脑经网口1发送录像，NET_RX | 左上 |
| 后摄 | HDMI-IN | 右上 |
| 左摄 | CAM0，OV5640 | 左下 |
| 右摄 | CAM1，OV3660 | 右下 |

1. 电脑Realtek实体有线网卡 → FPGA网口1（两个RJ45中离HDMI较远者）。
2. FPGA网口2（靠HDMI-OUT）→ 香橙派有线网口。
3. FPGA HDMI-OUT → 显示器。
4. 需要后视来源时，视频源HDMI-OUT → FPGA HDMI-IN。此来源与网口前摄独立。
5. 电脑通过原Wi-Fi访问香橙派管理地址192.168.0.4。

两条业务链路：

```text
电脑有线192.168.50.1/24 → FPGA网口1 192.168.50.2
FPGA网口2 192.168.60.2 → 香橙派有线192.168.60.1/24
```

不要把香橙派Wi-Fi管理地址192.168.0.4填成电脑有线业务地址。

## 2. 先处理WinError 10049

该错误发生在电脑发送程序绑定本地地址时。电脑网卡必须实际拥有192.168.50.1，只有169.254.x.x不能启动此发送端。它不是FPGA图像处理错误。

如果开发对话已经配置并确认地址有效，跳过本节，不要重复修改。

手动配置方法：

1. 先记录Realtek直连网卡的原IPv4、DHCP和DNS设置，方便恢复。
2. 按Win+R，输入`ncpa.cpl`，回车。
3. 找到实际接FPGA网口1的Realtek“以太网”，打开“属性”。不要选择Wi-Fi、虚拟网卡或香橙派一侧接口。
4. 进入“Internet协议版本4（TCP/IPv4）”属性，设置：
   - IP地址：`192.168.50.1`
   - 子网掩码：`255.255.255.0`
   - 默认网关：留空
   - DNS：不填写新的服务器，按原设置保留。
5. 确认保存，然后重开录像发送入口。

手动配置通常会持续保留，并非重启必然失效的临时地址。测试结束若要恢复，应按原记录恢复；原来是自动获取地址时，恢复自动获取。若由开发对话添加业务地址，以其实际变更记录和恢复方法为准；不能假定只删除一个地址就已恢复DHCP。

## 3. 确认FPGA位流

需要运行以下3.6.1候选；如果已经下载且没有断电丢失程序，不必重复下载。

[3.6.1 SOURCE_MAP候选位流](E:/zhoumian/FPGA/FPGA_GS/FPGA_GSV1/release/FPGA_GSV1_SOURCE_MAP_3_6_1_CANDIDATE/FPGA_GSV1_SOURCE_MAP_3_6_1_HDMI_1080P60.sbit)

SHA256：`b6e4ad93cb331c813651e53e771f3288c467a88aa155b3cc50eb7cbce59c25ea`

需要时使用原下载工具手动下载，不按复位键，不自动固化Flash。旧版本可能仍把网口视频作为右摄、上传CAM0，不能据此验收新来源映射。

## 4. 双击启动录像发送

1. 双击[启动前摄录像发送端](E:/zhoumian/FPGA/FPGA_GS/FPGA_GSV1/release/FPGA_GSV1_SOURCE_MAP_3_6_1_CANDIDATE/tools/start_front_video.cmd)。只开一份。
2. 在窗口中按需要勾选“循环（变更后从头播放）”。
3. 点“选择视频文件”，选择项目SC目录中的实际录像，例如：
   - 日间：`E:\zhoumian\FPGA\FPGA_GS\SC\SC_BT.mp4`
   - 夜间：`E:\zhoumian\FPGA\FPGA_GS\SC\SC_YJ.mp4`
4. 文件选择后会开始播放；仅在需要暂停或恢复时点“播放/暂停文件”。
5. 未选择文件时默认发送测试图案，看到测试图案不等于已发送道路录像。
6. 用FPGA KEY5切到“前摄”或四宫格左上，确认录像出现并持续变化。

本入口绑定192.168.50.1，发送到192.168.50.2，目标15fps，UDP50000。脚本内部仍使用`--role right`、`--right-fps`历史参数名，这是兼容发送端角色的内部名称；3.6.1把该输入映射为逻辑前摄。

程序会复用已有FFmpeg解码视频，不需要另装训练或转换环境。若报告找不到FFmpeg，应先核对既有解码器路径，不要重新构建FPGA。

## 5. 打开香橙派实时识别

1. 双击[启动实时NPU前摄](E:/zhoumian/FPGA/FPGA_GS/FPGA_GSV1/orangepi/m407/启动实时NPU前摄.cmd)。入口应复用匹配实例；不要另开旧前摄服务争抢UDP。
2. 打开[m407实时页面](http://127.0.0.1:18084/)。SSH转发需要保持，密码只在正常SSH终端输入。
3. 对照PC发送录像、FPGA前摄和网页原图，三处内容应一致，允许存在传输与处理延迟。
4. 香橙派网页可显示现有人车、道路/车道及交通灯叠加；实际无目标或证据不足时可能不出框或显示UNKNOWN。
5. 页面仍显示“来源待核对”时，由香橙派开发对话完成新固件来源确认；不能仅凭页面标题声称验收通过。

香橙派画框并不意味着FPGA HDMI也会显示这些框；本轮框和道路遮罩在网页上显示。FPGA仍显示原有图像、OSD和协议支持的反馈。

## 6. 最短联调顺序

1. 保持动态录像播放，确认前摄确为NET_RX。遮挡CAM0/CAM1不应使上传录像改变。
2. KEY5：前→后→左→右→四宫格；核对新方位。未接入来源可能无图。
3. KEY6：切换FPGA显示滤镜，网页收到的前摄原图不应随之变灰或换源。
4. KEY1左、KEY2右、KEY3直、KEY4停，每次动作间隔约3秒。网页应显示真实事件、引用帧、ACK及判定；证据不足允许UNKNOWN，不能将其当作完整驾驶规则通过。
5. 点击发送窗口的“停止/恢复网口前摄发送”，停发至少3秒，观察图像失效及旧识别清理；不应回退CAM0或香橙派本地录像。再点一次恢复。
6. 注意：“播放/暂停文件”只是冻结录像时间，发送端仍可持续发送静图；它不等于停止网络输入，不能用来验收断流。
7. 正常恢复后，可请香橙派端记录60秒实际接收、推理、网页新帧、丢帧和图龄。目标15fps不等于实测15fps。

## 7. 停止与恢复

1. 关闭PC网口发送窗口，停止向网口1发送视频。
2. 双击[停止M407候选](E:/zhoumian/FPGA/FPGA_GS/FPGA_GSV1/orangepi/m407/停止M407候选.cmd)。只关浏览器不会停止远端程序。
3. 如需恢复电脑有线网卡，按第2节记录还原IPv4、DHCP等原设置。
4. m407软件回退入口为[回退原前摄](E:/zhoumian/FPGA/FPGA_GS/FPGA_GSV1/orangepi/m407/回退原前摄.cmd)。软件回退不会自动恢复旧FPGA方位；硬件映射仍取决于实际下载的位流。
